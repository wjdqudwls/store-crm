# 00. 아이디어 정의

> 작성일: 2026-10-14 · 수정일: 2026-10-15 · 상태: **확정** (범위 세부는 [01-requirements.md](01-requirements.md)가 기준)
> `확인 필요` 표시는 아직 검증하지 않은 사실이나 가정이다.

## 1. 한 줄 정의

ERP와 연동된 매장 웹사이트에 **없던 상담 기록·콜리스트·고객 등급을**, 판매등록과 연결된 웹 서비스로 제공하는 패션 오프라인 매장용 CRM.

## 2. 왜 만드는가

- **목적(하나)**: 포트폴리오.
- **스토리**: 이커머스 담당 시절, 회사가 준비하던 고객 등급 체계와 CRM 자료를 엑셀 툴 하나로 먼저 구현해 4~5개 매장에 배포했다. 이 툴이 개발을 시작한 계기다. 개발을 배운 뒤, 같은 문제를 웹 서비스로 다시 풀었다.
- **주의**: 회사 등급 체계는 당시 산정 기준을 정하던 단계였고 **도입 전**이었다. "도입됐다"고 말하지 않는다.

## 3. 대상과 장면

| 대상 | 장면 |
| --- | --- |
| 매장 판매직원 | 고객이 방문하면 응대하고, 매장 웹사이트에 판매를 등록한다. 응대 직후 상담 내용은 별도 엑셀 파일에 남긴다. |
| 매장 판매직원 (CRM 시간) | 매장이 한가할 때 한 명은 응대, 한 명은 CRM을 맡는다. 매장 핸드폰으로 전화나 문자를 하고 결과를 콜리스트에 적는다. |
| 신규 고객 | 종이 고객등록카드(성명, 번호, 생년월일 선택, 주소 선택, 개인정보 동의)를 작성하면 직원이 웹사이트에 입력한다. |

- 대상에서 제외: 온라인 셀러(CONK 플랫폼 셀러). 오프라인 매장이 없으면 필요 없는 기능이 대부분이므로 **매장용으로 분리**한다.

## 4. 문제: 지금은 무엇으로 버티는가

| 도구 | 역할 | 빠진 것 |
| --- | --- | --- |
| 본사 ERP | 본사 업무, 매장 웹사이트와 연동 | 매장 직원은 직접 쓰지 않음 |
| 매장 웹사이트 (ERP 연동) | 판매등록, 고객등록 등 매장 업무 대부분 | **상담 내용, 콜리스트, 고객 등급** |
| 엑셀 파일 (콜리스트) | 상담 내용, 연락 결과 | 웹사이트의 고객 정보·구매이력과 분리 |

**핵심 문제**: 매장 웹사이트는 기능이 많았지만 고객 관계 관리 기능(상담 내용, 콜리스트, 등급)이 없었다. 그래서 이 부분만 별도 엑셀 파일로 관리했고, 고객 정보·구매이력과 상담 기록이 따로 놀았다.

**엑셀 CRM 툴(직접 제작)**: 흩어져 있던 매장 고객관리와 콜리스트를 하나의 엑셀로 합쳤다. 고객 정보, 구매이력, 상담 내용, 콜리스트에 회사가 준비하던 등급 산정까지 넣었다.

엑셀 CRM 툴이 정착하지 못한 이유:

1. 엑셀을 어려워하는 직원이 많았고, 이미 웹사이트에 익숙해서 엑셀 파일로 넘어오기 힘들다는 피드백이 있었다.
2. 판매 데이터를 담당자가 가공해 **주 1회** 엑셀로 다시 배포해야 했다. (반영 지연 때문에 곤란한 사례는 없었다.)
3. 결과적으로 사용자가 0명이 됐다.

## 5. 왜 엑셀이나 기존 시스템 대신 이걸 쓰는가

- **웹사이트에 없던 기능을 웹으로**: 상담 내용, 콜리스트, 등급을 직원이 이미 익숙한 웹 환경에서 쓴다. 엑셀로 넘어갈 필요가 없다.
- **엑셀 툴처럼 한 고객 화면에 합친다**: 고객 정보, 구매이력, 상담 내용, 콜리스트, 등급을 고객 한 명 기준으로 모아 본다.
- **자동으로 쌓인다**: 판매를 등록하면 구매이력과 등급이 즉시 갱신된다. 담당자의 주간 가공·배포가 사라진다.

## 6. 해결 구조

```
[매장 업무]                       [고객관리]
 판매등록 ──(판매 완료 이벤트)──▶  구매이력 반영 → 등급 재계산
 고객등록 ────────────────────▶  고객 프로필
                                   상담 메모 · 콜리스트 · 등급 기준
```

- 웹사이트 1개, 서버 1개, DB 1개 (운영비 0원 조건).
- 코드 안에서 '매장 업무'와 '고객관리'를 모듈로 분리하고 **이벤트로 연결**한다 (모듈러 모놀리스).
- 판매 데이터의 입구는 하나다. 나중에 엑셀 이관 등 새 출처는 같은 입구에 어댑터만 추가한다.

## 7. 범위

| 묶음 | MVP | 다음 | 나중 |
| --- | --- | --- | --- |
| 매장 업무 | 판매등록, 고객등록(매장 iPad · 본인 폰 QR · 직원 대리 입력) | SMS 인증 | POS 연동 |
| 데이터 입구 | 판매 이벤트 수신(멱등 처리), 더미 판매 생성기 | 엑셀 툴 데이터 이관 어댑터 | 파일 자동 수집 |
| 고객관리 | 고객 검색·상세, 구매이력, 등급 자동 산정, 등급 점수 근거 표시, 등급 변동 이력, 상담 메모 | 사이즈 분석 | |
| 콜리스트 | 필터 조합(등급, 마지막 방문일, 구매 카테고리, 담당자), 연락 결과 기록 | 생일 고객, 폰에서 바로 전화 | 알림톡/문자 발송 |
| 관리 | 로그인, 직원/관리자 역할, 등급 기준 설정 | 매장 관리 화면 | 대시보드 |
| 고객 식별 | 고객번호로 식별, 고객명 검색 → 목록 선택, 가족은 대표 1명 | 가족 구성원(구성원별 사이즈, 착용자 지정) | |
| 재고 | | | 매장별 재고, 입고, 매장 간 이동 |

상세 요구사항은 [01-requirements.md](01-requirements.md)에 있다.

## 8. 제약

- 1인, **8주**, 주 10~15시간 → 총 약 80~120시간.
- 예산: 월 운영비는 Claude 구독료뿐. 서버 비용이 들지 않는 배포 방식이 필요하다.
- 스택: Java/Spring Boot, JPA, MariaDB, Vue 3, Docker.
