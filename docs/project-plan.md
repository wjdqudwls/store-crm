## 4. 제품 방향

- **포지셔닝**: POS·ERP를 바꾸지 않고 옆에 붙는 "고객 기록" 도구. 결제는 매장 시스템에서 하고, 이 서비스는 실제 결제 금액과 고객 정보를 남긴다 (ADR-014).
- **차별점** (research.md 3장)
  1. 패션에 맞춘 고객 정보: 품목별 사이즈, 선호, 가족·착용자
  2. 구매 2일·2주·2달 후속 연락 할 일 (CAL-06, BR-14)
  3. 광고 연락 규칙 반영: 수신 동의, 홍보 단계 표시 (BR-08)
  4. 30초 기록, 상품은 선택 등록 + 엑셀 폼 (PRD-01·02)
- **시장 규모 (추정)**: 1:1 응대 패션 매장 약 3만~6만 곳, 직원 약 5만~15만 명. 근거는 2022년 개인 옷가게 사업자 87,881명(국세청)과 가정한 비율이다 (research.md 6장).
- **첫 사용자**: 혼자 결정하고 바로 쓸 수 있는 **개인 매장 사장**. 브랜드 매장은 본사 승인(개인정보 처리 위탁)이 필요해 그다음이다.
- **하지 않는 것**: 결제, POS 연동, 재고, 셀프형 매장의 자동 적립·쿠폰(무료 POS가 이미 잘한다, research.md 7장).

## 5. 범위와 우선순위

MVP 기능을 중요도로 나눈다. **Must**만으로 핵심 흐름(판매 기록 → 고객 상세 반영 → 오늘 할 일)을 시연할 수 있어야 한다.

| 우선순위 | 기능 | 밀리면 |
| --- | --- | --- |
| **Must** | 로그인·권한(AUTH-01·02), 직원 대리 고객등록·중복 확인(REG-01·04·05), 고객 검색·상세·구매이력·수정(CUS-01~04), 상품 화면 등록(PRD-01), 판매 기록·이벤트·반품·응대 메모·판매 내역(SAL-01~05, BR-12), 등급 산정·즉시 승급·근거·정기 산정·이력(GRD-01·02·03·05·06), 상담 메모(MEM-01~03), 콜리스트·연락 결과(CAL-01·02), 후속 연락 할 일(CAL-06), 더미 판매 생성기(ING-01), 무료 배포 | 줄이지 않는다 |
| **Should** | 키오스크 등록(REG-02), QR 등록(REG-03), 외국인 입력(REG-06), 가족 구성원(CUS-05), 상품 엑셀(PRD-02), 등급 기준 화면(GRD-04), 후속 연락 설정 화면(CAL-07), 직원 관리 화면(ADM-01), 성능 수치 기록(NFR-01·02) | 아래 줄이는 순서대로 '다음'이나 Swagger·기본값으로 대체 |
| **Could** | 판매 시 착용자 선택(CUS-05 일부) | 가장 먼저 뺀다 |
| **이번엔 안 함** | 01-requirements.md의 '다음'·'나중' 전부 (9장 로드맵) | - |

**시간이 밀리면 줄이는 순서 (제안)**: 01-requirements.md 10장의 4단계에 2개를 더한다.

1. 판매 시 착용자 선택 → 다음
2. QR 등록 → 다음
3. **상품 엑셀 → 화면 등록만 (제안)**
4. **후속 연락 설정 화면 → 기본값 고정 (제안)**
5. 등급 기준 화면 → Swagger
6. 직원 관리 화면 → Swagger와 시드 데이터

## 9. 작업 방식

- **역할**: 1인이 기획·설계·백엔드·프론트·테스트를 한다. 이번 목표가 개발 순서를 직접 익히는 것이라 핵심 로직(등급 규칙, 이벤트 처리, 금액 계산)은 직접 쓴다.
- **AI 활용**: 기획·문서·리뷰는 데스크톱 세션, 코드 작성 보조는 IntelliJ의 Claude Code. 둘 다 CLAUDE.md 규칙을 따른다. 기본 모델은 Sonnet, 어려운 설계·디버깅만 Opus.
- **결정 기록**: 업무 규칙은 01 8장, 기술 결정은 decisions.md(ADR). 확정 문서를 바꾸면 상단에 '변경' 줄을 단다.
- **브랜치와 PR**: 기획 문서는 `main`에 바로 커밋한다. 코드는 기능 브랜치 → PR → 테스트 통과 후 합친다 (`chore/backend-ci` PR이 합쳐진 뒤부터).
- **작업 시간 기록**: 날짜, 한 일, 걸린 시간을 매일 남긴다. 1주 차 끝과 매 마일스톤에 일정 재평가의 근거로 쓴다.
