# WBS (진행 순서와 상태)

> 작성일: 2026-10-30 · **매일 갱신** · 진행 순서는 이 문서가 기준이다 (01-requirements.md 8장 2026-10-30, ADR-032).
> 작업마다 할 일·완료 기준·먼저 쓸 실패 테스트는 [dev-plan.md](dev-plan.md), 날마다 쓴 시간은 [worklog.md](worklog.md)에 적는다. 마감(12/09)과 11/04 점검은 [project-plan.md](project-plan.md) 그대로다.
> 순서는 이전 프로젝트(CONK)에서 스크럼으로 다시 맞춘 실제 순서를 따른다: 기획 → 요구사항 → WBS → 화면 → 논리 ERD → 아키텍처·물리 ERD → 프론트 → 백엔드 → 인증 → 연동·배포.

## 갱신 규칙

- 작업을 시작하면 상태를 `진행`, 끝나면 `완료 (날짜)`로 바꾼다. 하루가 끝나면 worklog에 시간을 적고 아래 "지금" 줄을 고친다.
- 상태 값: `대기` · `진행` · `완료` · `뺌`(줄이는 순서로 빠짐, 01 10장).
- 개발(9~12단계)은 작업을 **하나씩** 한다. 기능 하나는 dev-plan.md 5장 순서(테스트할 경우 적기 → Repository → Service → Controller → 통합 → 정리 → PR)로 만든다.
- 작업 ID가 있는 코드 작업은 그 ID로 브랜치를 만든다 (예: `feat/B0-2-common-error`). 문서만 바꾸는 작업은 `main`에 바로 커밋한다.
